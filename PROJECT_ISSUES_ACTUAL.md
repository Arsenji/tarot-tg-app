### 2. Хардкод значений в коде

#### 2.1. YooKassa Service - Base URL
**Файл:** `backend/src/services/yookassa.ts:82`
```typescript
private baseUrl = 'https://api.yookassa.ru/v3'; // ❌ Хардкод
```
**Проблема:** URL не может быть изменен для тестовой/продакшн среды  
**Решение:** `private baseUrl = process.env.YOOKASSA_API_URL || 'https://api.yookassa.ru/v3';`

#### 2.2. Subscription Plans - Hardcoded Prices
**Файл:** `backend/src/services/yookassa.ts:56-77`
```typescript
export const SUBSCRIPTION_PLANS = {
  weekly: { price: '99.00', ... },
  monthly: { price: '299.00', ... },
  // ...
};
```
**Проблема:** Цены захардкожены, нельзя изменить без пересборки  
**Решение:** Вынести в переменные окружения:
```env
SUBSCRIPTION_PRICE_WEEKLY=99.00
SUBSCRIPTION_PRICE_MONTHLY=299.00
SUBSCRIPTION_PRICE_QUARTERLY=799.00
SUBSCRIPTION_PRICE_YEARLY=2990.00
```

#### 2.3. Rate Limiting - Hardcoded Values
**Файл:** `backend/src/middleware/rateLimit.ts`
**Проблема:** Значения rate limiting захардкожены в коде  
**Решение:** Вынести в env:
```env
RATE_LIMIT_WINDOW_MS=900000
RATE_LIMIT_MAX_REQUESTS=1000
RATE_LIMIT_AUTH_MAX_REQUESTS=100
```

#### 2.4. Cache TTL - Hardcoded Values
**Проблема:** TTL для кэша захардкожены в коде  
**Решение:** Вынести в env:
```env
CACHE_TTL_TAROT_CARDS=3600
CACHE_TTL_OPENAI=1800
CACHE_TTL_DAILY_ADVICE=86400
```

### 4. Проблемы с зависимостями

#### 4.1. Несоответствие версий зависимостей
**Проблема:** Разные версии одних и тех же пакетов в разных workspace  
**Примеры:**
- Express: backend `5.1.0`, admin-backend `4.18.2`
- bcryptjs: разные версии
- dotenv: разные версии

**Риск:** Непредсказуемое поведение, сложность отладки  
**Решение:** Унифицировать версии через корневой `package.json`

#### 4.2. @types пакеты в dependencies
**Проблема:** В `admin-backend/package.json` `@types/*` в `dependencies` вместо `devDependencies`  
**Риск:** Увеличение размера production bundle  
**Решение:** Переместить в `devDependencies`

---

### 5. Проблемы с базой данных

#### 5.1. Отсутствие миграций
**Проблема:** Нет системы миграций для MongoDB  
**Риск:** Сложность обновления схемы БД, возможные конфликты  
**Решение:** Добавить mongoose-migrate или аналог

#### 5.2. Отсутствие индексов
**Проблема:** Не все часто запрашиваемые поля проиндексированы  
**Риск:** Медленные запросы при росте данных  
**Решение:** Добавить индексы на:
- `User.telegramId`
- `User._id`
- `TarotReading.userId`
- `TarotReading.createdAt`
- `SupportMessage.telegramId`

#### 5.3. MongoDB timeouts - Hardcoded
**Проблема:** Таймауты подключения захардкожены  
**Решение:** Вынести в env:
```env
MONGO_MAX_POOL_SIZE=10
MONGO_SERVER_TIMEOUT=5000
MONGO_SOCKET_TIMEOUT=45000
```

## 🟡 СРЕДНИЕ ПРОБЛЕМЫ

### 6. Проблемы с кодом

#### 6.1. Отсутствие обработки ошибок
**Проблема:** Не все async функции имеют try-catch  
**Риск:** Непредсказуемые падения приложения  
**Решение:** Добавить централизованную обработку ошибок

#### 6.2. Дублирование кода
**Проблема:** Похожий код в разных местах  
**Примеры:**
- Валидация токенов
- Обработка ошибок API
- Форматирование данных

**Решение:** Вынести общую логику в utils

#### 6.3. Отсутствие error boundaries (Frontend)
**Проблема:** Нет error boundaries в React  
**Риск:** Весь app падает при ошибке  
**Решение:** Добавить Error Boundaries

---

### 7. Проблемы с API

#### 7.1. Отсутствие версионирования API
**Проблема:** Нет версии в URL (`/api/v1/...`)  
**Риск:** Сложность обновления без breaking changes  
**Решение:** Добавить версионирование API

#### 7.2. Нет документации API
**Проблема:** Отсутствует OpenAPI/Swagger документация  
**Риск:** Сложность разработки frontend/интеграций  
**Решение:** Добавить Swagger документацию

#### 7.3. Неполная валидация входных данных
**Проблема:** Не все endpoints проверяют входные данные  
**Риск:** NoSQL injection, XSS  
**Решение:** Добавить middleware валидации на все endpoints

---

### 8. Проблемы с Telegram Bot

#### 8.1. Отсутствие обработки ошибок Telegram API
**Проблема:** Не обрабатываются ошибки от Telegram API  
**Риск:** Падения при недоступности API  
**Решение:** Добавить retry логику и graceful degradation

#### 8.2. Отсутствие очереди для сообщений
**Проблема:** Сообщения отправляются сразу, без очереди  
**Риск:** Превышение rate limits Telegram  
**Решение:** Добавить очередь для отправки сообщений (Bull/BullMQ)

---

### 9. Проблемы с производительностью

#### 9.1. Нет кэширования запросов
**Проблема:** Повторные запросы идут в БД без кэша  
**Риск:** Лишняя нагрузка на БД  
**Решение:** Использовать Redis для кэширования (уже подключен, но не везде используется)

#### 9.2. Большой размер bundle (Frontend)
**Проблема:** Frontend bundle может быть излишне большим  
**Риск:** Медленная загрузка  
**Решение:** Настроить code splitting, lazy loading
