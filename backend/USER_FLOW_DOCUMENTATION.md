# 📋 Логика работы приложения: Пользователи с подпиской и без подписки

## 🔐 Система проверки доступа

### Администратор
- **ID администратора:** определяется через `ADMIN_TELEGRAM_ID` в переменных окружения
- **Доступ:** Полный неограниченный доступ ко всем функциям
- **Ограничения:** Нет

---

## 👤 Пользователь БЕЗ подписки

### Доступные функции:

#### ✅ 1. **Yes/No расклад** (1 раз в день)
- **Лимит:** 1 расклад в день
- **Проверка:** Поле `lastYesNoDate` в базе данных
- **Логика:**
  1. При первом использовании сегодня: `lastYesNoDate` не сегодня → разрешено
  2. После использования: `lastYesNoDate` устанавливается на сегодня → заблокировано до следующего дня
  3. При попытке использовать повторно сегодня → показывается модальное окно с предложением подписки
  4. На следующий день → снова доступно 1 использование

#### ✅ 2. **Совет дня (Daily Advice)** (1 раз в день)
- **Лимит:** 1 совет в день
- **Проверка:** Поле `lastDailyAdviceDate` в базе данных
- **Логика:**
  1. При первом использовании сегодня: `lastDailyAdviceDate` не сегодня → разрешено
  2. После использования: `lastDailyAdviceDate` устанавливается на сегодня → заблокировано до следующего дня
  3. При попытке использовать повторно сегодня → показывается модальное окно с предложением подписки
  4. На следующий день → снова доступно 1 использование

#### ✅ 3. **Три карты (Three Cards)** (1 раз в день)
- **Лимит:** 1 расклад в день
- **Проверка:** Поле `lastThreeCardsDate` в базе данных
- **Логика:**
  1. При первом использовании сегодня: `lastThreeCardsDate` не сегодня → разрешено
  2. После использования: `lastThreeCardsDate` устанавливается на сегодня → заблокировано до следующего дня
  3. При попытке использовать повторно сегодня → показывается модальное окно с предложением подписки
  4. На следующий день → снова доступно 1 использование

#### ❌ 4. **История раскладов**
- **Доступ:** Заблокирован
- **При попытке просмотра:** Показывается модальное окно с предложением подписки
- **Ошибка API:** `403 History is available only for subscribed users`
- **Важно:** Расклады НЕ сохраняются в базу данных для пользователей без подписки

### Статус подписки (API `/api/tarot/subscription-status`):
```json
{
  "hasSubscription": false,
  "canUseDailyAdvice": true/false,  // true если еще не использовал сегодня
  "canUseYesNo": true/false,  // true если еще не использовал сегодня
  "canUseThreeCards": true/false,  // true если еще не использовал сегодня
  "remainingDailyAdvice": 1 или 0,  // 1 если еще не использовал сегодня, 0 если использовал
  "remainingYesNo": 1 или 0,  // 1 если еще не использовал сегодня, 0 если использовал
  "remainingThreeCards": 1 или 0  // 1 если еще не использовал сегодня, 0 если использовал
}
```

### Визуальные индикаторы:
- Кнопки активны, если еще не использовал функцию сегодня
- Показывается счетчик: "Осталось: 1" для каждой функции (если не использовал сегодня)
- После использования показывается "Использовано" до следующего дня
- История раскладов недоступна (вкладка может быть скрыта или показывать модальное окно)

- **Проверка:** `hasSubscription === true`

- **История:** Сохраняется в базу данных

#### ✅ 2. **Совет дня (Daily Advice)**
- **Лимит:** Неограниченно
- **Проверка:** `hasSubscription === true`
- **Логика:** Всегда разрешено, без ограничений
- **История:** Сохраняется в базу данных

#### ✅ 3. **Три карты (Three Cards)**
- **Лимит:** Неограниченно

## 🔄 Процесс работы

### 1. Регистрация нового пользователя
```
Пользователь открывает бота → /start
↓
Создается запись в БД:
- subscriptionStatus: 0 (нет подписки)
- freeYesNoUsed: false (не использовал бесплатный Yes/No)
- subscriptionExpiresAt: null
```

### 2. Использование Yes/No (без подписки)
```
Пользователь нажимает "Да/Нет"
↓
Проверка: lastYesNoDate === сегодня?
  ├─ Нет → Разрешить
  │   ↓
  │   Выполнить расклад
  │   ↓
  │   markFreeYesNoUsed() → lastYesNoDate = сегодня
  │   ↓
  │   НЕ сохранять в историю (нет подписки)
  │
  └─ Да → Заблокировать
      ↓
      API возвращает 403
      ↓
      Фронтенд показывает модальное окно подписки
```

### 3. Использование Daily Advice (без подписки)
```
Пользователь нажимает "Совет дня"
↓
Проверка: lastDailyAdviceDate === сегодня?
  ├─ Нет → Разрешить
  │   ↓
  │   Выполнить расклад
  │   ↓
  │   markDailyAdviceUsed() → lastDailyAdviceDate = сегодня
  │   ↓
  │   НЕ сохранять в историю (нет подписки)
  │
  └─ Да → Заблокировать
      ↓
      API возвращает 403
      ↓
      Фронтенд показывает модальное окно подписки
```

### 4. Использование Three Cards (без подписки)
```
Пользователь нажимает "Три карты"

Проверка: lastThreeCardsDate === сегодня?
  ├─ Нет → Разрешить
  │   ↓
  │   Выполнить расклад
  │   ↓
```

### 5. Попытка просмотреть историю (без подписки)
```
Пользователь нажимает "История раскладов"
↓
Проверка: hasSubscription === true?
  ├─ Да → Разрешить
  │   ↓
  │   Показать историю
  │
  └─ Нет → Заблокировать
      ↓
      API возвращает 403
      ↓
      Фронтенд показывает модальное окно подписки
```

### 4. Покупка подписки
```
Пользователь нажимает "Купить подписку"
↓
Выбор тарифа (1 месяц, 3 месяца, 12 месяцев)
↓
Оплата через YooKassa
↓
Webhook от YooKassa → activateSubscription()
↓
Обновление в БД:
- subscriptionStatus: 1
- subscriptionExpiresAt: текущая дата + длительность тарифа
↓
Пользователь получает полный доступ
```

### 5. Истечение подписки
```
Проверка при каждом запросе:
subscriptionExpiresAt < текущая дата?
  ├─ Да → subscriptionStatus остается 1, но доступ блокируется
  │   (или автоматически сбрасывается в 0)
  │
  └─ Нет → Доступ разрешен
```

## 🔍 Технические детали

### Проверка подписки
```typescript
checkSubscriptionStatus(telegramId) → {
  hasSubscription: boolean,  // subscriptionStatus === 1 && expiresAt > now
  isExpired: boolean,
  expiresAt?: Date,
  daysRemaining?: number
}
```

### Проверка бесплатного Yes/No
```typescript
hasUsedFreeYesNo(telegramId) → boolean  // freeYesNoUsed === true
```

### Логика доступа к Yes/No
```typescript
if (hasSubscription || isAdmin || !hasUsedFree) {
  // Разрешить
} else {
  // Заблокировать
}
```

### Логика доступа к Daily Advice и Three Cards
```typescript
if (hasSubscription || isAdmin) {
  // Разрешить
} else {
  // Заблокировать
}
```

## 🎯 Важные моменты

1. **Бесплатные функции** - по 1 разу в день для каждого типа расклада
2. **Лимиты сбрасываются** каждый день в полночь (по времени сервера)
3. **Подписка** дает неограниченный доступ ко всем функциям
4. **Администратор** всегда имеет полный доступ, независимо от подписки
5. **История раскладов** доступна только пользователям с подпиской
6. **Расклады без подписки** НЕ сохраняются в базу данных
7. **Уточняющие вопросы** доступны только если есть доступ к основному раскладу

## 🐛 Текущее состояние (для отладки)

⚠️ **ВНИМАНИЕ:** В коде есть временные отладочные флаги `|| true`, которые разрешают всем пользователям использовать все функции. Это нужно убрать в продакшене!

```typescript
// Временная отладка (нужно убрать):
canUseDailyAdvice: subscriptionStatus.hasSubscription || isAdmin || true
canUseYesNo: subscriptionStatus.hasSubscription || isAdmin || !hasUsedFreeYesNoValue || true
canUseThreeCards: subscriptionStatus.hasSubscription || isAdmin || true
```

После удаления этих флагов логика будет работать как описано выше.
