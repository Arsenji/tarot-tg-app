# 📋 Логика работы приложения: Пользователи с подпиской и без подписки

## 🔐 Система проверки доступа

### Администратор
- **ID администратора:** определяется через `ADMIN_TELEGRAM_ID` в переменных окружения
- **Доступ:** Полный неограниченный доступ ко всем функциям
- **Ограничения:** Нет

---

## 👤 Пользователь БЕЗ подписки

### Доступные функции:

#### ✅ 1. **Yes/No расклад** (1 раз бесплатно)
- **Лимит:** 1 бесплатный расклад навсегда
- **Проверка:** Флаг `freeYesNoUsed` в базе данных
- **Логика:**
  1. При первом использовании: `freeYesNoUsed = false` → разрешено
  2. После использования: `freeYesNoUsed = true` → заблокировано
  3. При попытке использовать повторно → показывается модальное окно с предложением подписки

#### ❌ 2. **Совет дня (Daily Advice)**
- **Доступ:** Заблокирован
- **При попытке использования:** Показывается модальное окно с предложением подписки
- **Ошибка API:** `403 Subscription required`

#### ❌ 3. **Три карты (Three Cards)**
- **Доступ:** Заблокирован
- **При попытке использования:** Показывается модальное окно с предложением подписки
- **Ошибка API:** `403 Subscription required`

### Статус подписки (API `/api/tarot/subscription-status`):
```json
{
  "hasSubscription": false,
  "canUseDailyAdvice": false,
  "canUseYesNo": true/false,  // true если еще не использовал бесплатный
  "canUseThreeCards": false,
  "remainingDailyAdvice": 0,
  "remainingYesNo": 1 или 0,  // 1 если еще не использовал, 0 если использовал
  "remainingThreeCards": 0
}
```

### Визуальные индикаторы:
- Кнопки заблокированных функций могут быть затемнены или с иконкой 🔒
- Показывается счетчик: "Осталось: 1" для Yes/No (если не использовал)
- После использования Yes/No показывается "Использовано"

## 💎 Пользователь С подпиской

### Доступные функции:

#### ✅ 1. **Yes/No расклад**
- **Лимит:** Неограниченно
- **Проверка:** `hasSubscription === true`
- **Логика:** Всегда разрешено, без ограничений

#### ✅ 2. **Совет дня (Daily Advice)**
- **Лимит:** Неограниченно
- **Проверка:** `hasSubscription === true`
- **Логика:** Всегда разрешено, без ограничений

#### ✅ 3. **Три карты (Three Cards)**
- **Лимит:** Неограниченно
- **Проверка:** `hasSubscription === true`
- **Логика:** Всегда разрешено, без ограничений

### Статус подписки (API `/api/tarot/subscription-status`):
```json
{
  "hasSubscription": true,
  "canUseDailyAdvice": true,
  "canUseYesNo": true,
  "canUseThreeCards": true,
  "remainingDailyAdvice": -1,  // -1 означает неограниченно
  "remainingYesNo": -1,
  "remainingThreeCards": -1
}
```

### Визуальные индикаторы:
- Все кнопки активны
- Счетчики не показываются (или показывается "∞")
- Может отображаться информация о сроке действия подписки

## 🔄 Процесс работы

### 1. Регистрация нового пользователя
```
Пользователь открывает бота → /start
↓
Создается запись в БД:
- subscriptionStatus: 0 (нет подписки)
- freeYesNoUsed: false (не использовал бесплатный Yes/No)
- subscriptionExpiresAt: null
```

### 2. Использование Yes/No (без подписки)
```
Пользователь нажимает "Да/Нет"
↓
Проверка: freeYesNoUsed === false?
  ├─ Да → Разрешить
  │   ↓
  │   Выполнить расклад
  │   ↓
  │   markFreeYesNoUsed() → freeYesNoUsed = true
  │
  └─ Нет → Заблокировать
      ↓
      Показать модальное окно подписки
```

### 3. Попытка использовать Daily Advice (без подписки)
```
Пользователь нажимает "Совет дня"
↓
Проверка: hasSubscription === true?
  ├─ Да → Разрешить
  │
  └─ Нет → Заблокировать
      ↓
      API возвращает 403
      ↓
      Фронтенд показывает модальное окно подписки
```

### 4. Покупка подписки
```
Пользователь нажимает "Купить подписку"
↓
Выбор тарифа (1 месяц, 3 месяца, 12 месяцев)
↓
Оплата через YooKassa
↓
Webhook от YooKassa → activateSubscription()
↓
Обновление в БД:
- subscriptionStatus: 1
- subscriptionExpiresAt: текущая дата + длительность тарифа
↓
Пользователь получает полный доступ
```

### 5. Истечение подписки
```
Проверка при каждом запросе:
subscriptionExpiresAt < текущая дата?
  ├─ Да → subscriptionStatus остается 1, но доступ блокируется
  │   (или автоматически сбрасывается в 0)
  │
  └─ Нет → Доступ разрешен
```

## 🔍 Технические детали

### Проверка подписки
```typescript
checkSubscriptionStatus(telegramId) → {
  hasSubscription: boolean,  // subscriptionStatus === 1 && expiresAt > now
  isExpired: boolean,
  expiresAt?: Date,
  daysRemaining?: number
}
```

### Проверка бесплатного Yes/No
```typescript
hasUsedFreeYesNo(telegramId) → boolean  // freeYesNoUsed === true
```

### Логика доступа к Yes/No
```typescript
if (hasSubscription || isAdmin || !hasUsedFree) {
  // Разрешить
} else {
  // Заблокировать
}
```

### Логика доступа к Daily Advice и Three Cards
```typescript
if (hasSubscription || isAdmin) {
  // Разрешить
} else {
  // Заблокировать
}
```

---

## 🎯 Важные моменты

1. **Бесплатный Yes/No** - это одноразовая возможность, не восстанавливается
2. **Подписка** дает неограниченный доступ ко всем функциям
3. **Администратор** всегда имеет полный доступ, независимо от подписки
4. **История раскладов** доступна всем пользователям
5. **Уточняющие вопросы** доступны только если есть доступ к основному раскладу

## 🐛 Текущее состояние (для отладки)

⚠️ **ВНИМАНИЕ:** В коде есть временные отладочные флаги `|| true`, которые разрешают всем пользователям использовать все функции. Это нужно убрать в продакшене!

```typescript
// Временная отладка (нужно убрать):
canUseDailyAdvice: subscriptionStatus.hasSubscription || isAdmin || true
canUseYesNo: subscriptionStatus.hasSubscription || isAdmin || !hasUsedFreeYesNoValue || true
canUseThreeCards: subscriptionStatus.hasSubscription || isAdmin || true
```

После удаления этих флагов логика будет работать как описано выше.
